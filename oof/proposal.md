# [cite_start]Research Proposal: Graph Topologies and Incentive Stability in Multi-Agent Code Generation [cite: 1]
[cite_start]**Name:** Nana Ye, Charlotte Ma, Jason Liu [cite: 2]

## [cite_start]Introduction, Prior Works & Motivation [cite: 3]
[cite_start]Multi-agent LLM systems have recently shown strong gains in code generation by decomposing software development into specialized roles and introducing structured feedback. [cite: 4] [cite_start]Frameworks such as MetaGPT and AutoGen formalize role-based coordination, while iterative approaches like AgentCoder, Reflexion, and MapCoder demonstrate that closed-loop testing and reflection can substantially improve correctness on benchmarks such as Mostly Basic Programming Problems (MBPP) (Hong et al., 2023; Wu et al., 2024; Huang et al., 2023; Shinn et al., 2023; Islam et al., 2024; Austin et al., 2021). [cite: 5] [cite_start]However, existing systems are typically evaluated as holistic pipelines in which many factors change simultaneously: agent roles, prompts, tools, and stopping rules. [cite: 6] [cite_start]As a result, it remains unclear how much of the observed performance gain arises specifically from the interaction graph structure. [cite: 7] [cite_start]This lack of controlled analysis limits our understanding of how different topologies shape agents' incentives to spend tokens on verification under constrained budgets. [cite: 8] [cite_start]As AI usage in software engineering scales in the near-future, inefficient multi-agent systems could lead to massively wasted compute costs. [cite: 9]

[cite_start]This project evaluates how these graph structures affect the tradeoff between accuracy and compute cost on the MBPP benchmark using a fixed model (GPT-40) (Austin et al., 2021). [cite: 10] [cite_start]Specifically, we investigate whether complex graph structures discourage high-effort verification from agents due to varying incentives. [cite: 11] [cite_start]We analyze multi-agent interactions through the lens of Cooperative Game Theory, where the successful completion of a coding task (pass@1) is treated as a payoff generated by a team of agents. [cite: 12] [cite_start]We utilize the Shapley value to provide an axiomatic, fair allocation of success by measuring the marginal contributions of each agent role within specific graphs (Shapley, 1953). [cite: 13] [cite_start]Furthermore, we apply a utility-based framework to study incentive-stability. [cite: 14] [cite_start]We define utility as the balance between task success and cost of tokens of effort, and we use it to determine whether a graph structure supports an approximate Nash Equilibrium where all agents are incentivized to perform high effort verification under constrained compute costs (Shoham & Leyton-Brown, 2008). [cite: 14]

## [cite_start]Problem Statement [cite: 15]

* [cite_start]**Agents:** Planner (PL), Coder (C), Reviewer (R), and Tester (T). [cite: 16]
* [cite_start]**Actions:** Each agent $i$ selects an effort level $e_i \in \{0,1\}$, where higher effort corresponds to more rigorous reasoning or verification and incurs a cost $C_i(e_i)$ measured by token usage and interaction rounds. [cite: 17]
* [cite_start]**Outcome:** For task $x$ and graph $g$, the protocol runs for at most $K$ rounds and terminates with $Y \in \{\text{pass}, \text{fail}\}$ based on unit-test execution. [cite: 18]
* [cite_start]**Utility:** Each agent's utility is $U_i = V \cdot \mathbf{1}[Y=\text{pass}] - \lambda \cdot T_i$, where $V>0$ is the value of success, $\lambda>0$ scales compute cost, and $T_i$ refers to token expenditure for agent $i$. [cite: 19]

[cite_start]Graphs are compared by pass@1, total tokens, and whether the high-effort profile $e^* = (1,1,1,1)$ is an approximate Nash equilibrium. [cite: 20] [cite_start]We want to investigate whether there exists a graph configuration such that for every agent and some reasonably small $\epsilon$, the following condition holds: [cite: 21]

$$U_i(e_i=1, e_{-i}^*) \geq U_i(e_i=0, e_{-i}^*) - \epsilon$$

## Methodology [cite: 22]
**Graph configurations:** We compare interaction graphs that differ only in topology and stopping rules, holding the model, tasks, and role prompts fixed: [cite: 23]
* [cite_start]**G0: Single-Agent Baseline.** One-shot solution, optional self-check. [cite: 24]
* [cite_start]**G1: Waterfall Pipeline.** Sequential $PL \rightarrow C \rightarrow R \rightarrow T$ with minimal feedback. [cite: 25]
* [cite_start]**G2: AgentCoder-Style Loop.** Iterative code-test-revise until tests pass or budget is exhausted. [cite: 26]
* [cite_start]**G3: MapCoder-Style Cycle.** Retrieval-planning-coding-debugging under a fixed budget. [cite: 27]

[cite_start]All graphs are implemented in a common orchestration framework (e.g., LangGraph); no fine-tuning or GPU resources are used. [cite: 28]

[cite_start]**Benchmark and metrics:** Evaluation is conducted on MBPP. [cite: 29] [cite_start]We report pass@1, total tokens, interaction rounds, and the stage where errors are first detected (review vs. testing). [cite: 29]

[cite_start]**Incentive stability:** For each graph, we perform an empirical best-response test by forcing one role to low effort while others remain high and estimating the utility change $\Delta U_i$. [cite: 30] [cite_start]A graph supports stable high-effort verification if no role benefits from unilateral deviation. [cite: 31]

[cite_start]**Shapley attribution:** Let $v_g(S)$ denote expected pass@1 when only roles $S$ are active. [cite: 32] [cite_start]Shapley values are estimated via permutation sampling, $\phi_i(g) = \mathbb{E}_{\pi} [v_g(S_{\pi}^i \cup \{i\}) - v_g(S_{\pi}^i)]$, to quantify each role's marginal contribution under different graphs. [cite: 33]

[cite_start]**Technical Challenges:** Several challenges still exist for our study particularly on computational cost and effort manipulation. [cite: 34] [cite_start]First, estimating Shapley values requires evaluating many subsets of agents, which can be expensive even with a small number of roles. [cite: 35] [cite_start]We could potentially address this by using permutation-based Monte Carlo estimation and limiting evaluation to a representative subset of MBPP tasks. [cite: 36] [cite_start]Second, because we do not fine-tune models, effort levels must be operationalized through prompt constraints, token budgets, and stopping rules. [cite: 37] [cite_start]Ensuring that "low effort" and "high effort" conditions are comparable across graphs is nontrivial and would require prompt and budget calibration. [cite: 38]

### [cite_start]Introduction [cite: 58]
[cite_start]Multi-agent coding systems improve reliability by decomposing software development into specialized roles and introducing feedback loops. [cite: 59] [cite_start]However, the efficacy of these systems is highly dependent on their interaction graph structure. [cite: 60] [cite_start]While linear pipelines are simple, iterative test loops and multi-stage cycles alter mechanisms for information flow, error discovery, and incentives to spend tokens on verification. [cite: 61] [cite_start]This project evaluates how these graph structures affect the tradeoff between accuracy and compute cost on the MBPP benchmark using a fixed model (GPT-40). [cite: 62] [cite_start]Specifically, we investigate whether complex graph structures discourage high-effort verification from agents due to varying incentives. [cite: 63]

### [cite_start]Previous Work [cite: 68]
[cite_start]Early work on code generation studied whether large language models can synthesize short programs from natural-language descriptions, and introduced benchmarks to measure functional correctness. [cite: 69] Austin et al. (2021) [cite_start]proposed the Mostly Basic Programming Problems (MBPP) dataset (974 Python tasks) and used it to evaluate program synthesis performance under few-shot prompting and fine-tuning. [cite: 70] [cite_start]MBPP-style unit-test evaluation is now a standard way to compare code-generation methods. [cite: 71]

[cite_start]A major recent trend is to decompose software development into specialized agent roles (e.g., planner/architect/engineer/tester) and orchestrate them with explicit workflows. [cite: 72] [cite_start]MetaGPT formalizes this idea by encoding "standard operating procedures" (SOPs) into prompt sequences, aiming to reduce cascading errors when chaining multiple LLM steps (Hong et al., 2023). [cite: 73] [cite_start]Frameworks such as AutoGen generalize this direction by providing infrastructure to define multi-agent conversation patterns and integrate tools/humans, treating interaction patterns as configurable components of a broader agent system (Wu et al., 2024). [cite: 74] [cite_start]These systems demonstrate that multi-agent decomposition can improve reliability, but they are typically evaluated as end-to-end packages, where multiple design choices (roles, prompts, tools, and stopping rules) change at once. [cite: 75]

[cite_start]Another strong line of work improves code generation through closed-loop iteration: generate code, execute tests (or use other feedback), and revise. [cite: 76] [cite_start]AgentCoder introduces explicit roles for a programmer, test designer, and test executor, using iterative testing feedback to guide refinement. [cite: 77, 78] [cite_start]In a related spirit (Huang et al., 2023), Reflexion shows that language agents can incorporate feedback through "reflection" text that conditions future attempts, improving performance across tasks without updating model weights (Shinn et al., 2023). [cite: 79] [cite_start]Beyond simple code-test loops, MapCoder proposes a multi-agent program-synthesis cycle with agents for recalling examples, planning, coding, and debugging, aiming to mirror how humans solve programming problems in stages (Islam et al, 2024). [cite: 80] [cite_start]These approaches provide strong evidence that iteration and structured stages can improve correctness, but they often do not isolate the interaction topology itself (pipeline vs. loop vs. richer cycle) as the primary variable under controlled conditions. [cite: 81]

[cite_start]These works provide compelling demonstrations that role specification, execution feedback, and richer agent tooling can improve coding outcomes. [cite: 82] [cite_start]Yet there remains limited controlled evidence about how much of the benefit comes specifically from the interaction graph structure, and limited analysis of role contribution and incentive effects under compute costs. [cite: 83] [cite_start]This motivates our project's focus on systematically comparing representative topologies under fixed model and benchmark conditions, then analyzing contribution and verification incentives using cooperative-game and utility-based lenses. [cite: 84]
